# ตรวจคำและข้อความ Kemtit ทั้งระบบ

วันที่: 2026-10-02 · สถานะ: ตรวจและปรับเสร็จ ผ่าน local verification ตามขอบเขตนี้

## ขอบเขต

ตรวจข้อความกลาง 48 หมวด รวม 1,368 รายการต่อภาษา ทั้งไทยและอังกฤษ ครอบคลุมเมนู ปุ่ม ฟอร์ม คำแนะนำ สถานะ empty/error ข้อความแจ้งเตือน และ accessible labels ประกอบกับ source consumers และการตรวจหน้าจอจริงบางเส้นทาง

การตรวจนี้ไม่เปลี่ยน identifier, schema, API, route หรือข้อมูลที่ผู้ใช้กรอก คงชื่อแบรนด์ รูปแบบไฟล์ และคีย์ลัดที่มีความหมายจริงไว้ `/prototype` เป็นตัวอย่างภาพภาษาอังกฤษที่แยกจาก product catalogs; ไม่ย้าย fixture หรือคำอธิบาย demo เข้ามาในระบบจริง

## หลักที่ใช้ตัดสิน

1. คำเรียกรายการเดียวกันต้องสอดคล้องกันระหว่างหน้า โดยแยกงาน นัดหมาย โน้ต กิจวัตร บิล และรายจ่ายชัดเจน
2. ปุ่มบอกผลของการกดจริง เช่น เพิ่มงาน บันทึก ตั้งเป้าหมาย ไม่ใช้ข้อความกว้างที่ทำให้เดา
3. รองรับจอสัมผัสก่อน: มีปุ่มกดและคำแนะนำถึงปุ่มนั้น ส่วน Enter/คีย์ลัดเป็นทางเลือก
4. ใช้ภาษาของผู้ใช้ แทนศัพท์เชิงระบบ เช่น ความจุ บริบท หรือข้อมูลจริง เมื่อมีคำที่ตรงและชัดกว่า
5. ไม่สัญญาว่าระบบทำงานแทนผู้ใช้หรือมีความสามารถที่ไม่มี เช่น จ่ายเงิน ออกใบแจ้งหนี้ หรือทำธุรกรรม แต่คำแนะนำขั้นตอนอาชีพสามารถกล่าวถึงงานที่ผู้ใช้ต้องทำภายนอกระบบได้
6. คงความหมายของการลบ การเก็บ และการกู้คืนให้แยกกัน ไม่ใช้คำที่ชวนให้คิดว่าข้อมูลหายถาวรกับการเก็บที่เรียกคืนได้
7. รักษา ICU placeholders, จำนวน/หน่วย, วันที่ และเงื่อนไขของข้อความ ไม่แปลชื่อผู้ใช้หรือข้อมูลที่กรอก

## หลักฐานตั้งต้น

- Catalog key parity, ภาษาไทย/อังกฤษ และ placeholders: 7 tests ผ่านก่อนรอบแก้คำ
- Typecheck และ QuickTaskInput lint ผ่านก่อน audit
- QuickTaskInput: เอาคำสั่ง Enter ออกจาก placeholder และใช้ปุ่มหลัก “เพิ่มงาน” / “Add task”; แตะเพิ่มจริงบน 390px และ 768px สำเร็จ
- Today/Life ใช้ “กิจวัตร” และ “นิสัย” ไม่ตรงกันสำหรับ entity เดียวกัน
- Inbox note composer มีปุ่ม “บันทึก” แต่ hint เดิมกล่าวถึง Enter อย่างเดียว
- Production TSX literal search พบส่วนใหญ่เป็น comments, การตรวจหน่วยบาท และอักษรตกแต่ง K/G; ไม่พบ prose ที่ hardcode ชัดเจนจากรูปแบบที่ค้น ไม่ตีความว่าครอบคลุมทุก runtime value

## ผลและการตรวจหลังแก้

รวมผลจาก `keyword-audit-navigation-2026-10-02.json` (459 รายการ/ภาษา), `keyword-audit-planning-2026-10-02.json` (442), และ `keyword-audit-records-2026-10-02.json` (467) รวม 1,368 รายการ/ภาษา ตรวจสอบชุดหมวดแล้วครบ 48 หมวด ไม่มีซ้ำหรือขาด

### คำที่ใช้ให้สอดคล้องกัน

| ความหมาย | ไทย | English |
| --- | --- | --- |
| Task | งาน / เพิ่มงาน | Task / Add task |
| Habit entity | กิจวัตร | Habit |
| Note entity | โน้ต | Note |
| Context on a numeric entry | หมายเหตุ | Note |
| Project entity | โปรเจกต์ | Project |
| Reversible archive | เก็บในคลัง / คลังเก็บ / กู้คืน | Archive / Restore |
| Remaining daily minutes | เวลาที่เหลือวันนี้ | Time left today |

คำว่า “สร้างนิสัย” ในประโยคทั่วไปยังคงไว้ได้ ส่วน “รายการ” ในหัวตารางยอดบันทึกคงไว้ เพราะคอลัมน์นั้นแสดงทั้งหมายเหตุ เป้าหมาย และรายการปรับยอด

### การตัดสินข้อเสนอ

- แก้ required expense placeholder ที่สื่อว่าปล่อยว่างได้ โดยแยกจาก bill amount ที่ไม่บังคับกรอก
- คำแนะนำโน้ตกล่าวถึงปุ่มบันทึกก่อนคีย์ลัด; การเพิ่มงานวันนี้มีปุ่ม “เพิ่มงาน” ชัดเจน
- แก้คำเรียก Habit/Archive/Note ข้ามหน้าให้สอดคล้องกัน รวมข้อความแจ้งเตือน
- แก้ชื่อสำหรับโปรแกรมอ่านหน้าจอให้ตรงปลายทาง Today และใช้ชื่อ checkbox ที่รองรับทั้งสถานะเสร็จ/ยังไม่เสร็จ
- แก้ข้อความ LINE ให้ระบุการเลือกเปิดแจ้งเตือนและช่องทางส่ง ไม่สื่อว่าเชื่อมแล้วจะเปิดทุกการแจ้งเตือนเอง
- คำแนะนำติดตั้งกล่าวถึง iPad; การแนบรูปบอกว่าเลือกรูป และระบุ WebP ตามชนิดที่ระบบรับอยู่แล้ว
- ไม่รับข้อเสนอเปลี่ยนงานออกใบแจ้งหนี้เป็น “งานเตรียมใบแจ้งหนี้” ทั้งชุด เพราะบางจุดทำให้ความหมายงานธุรกิจคลาดเคลื่อน และคำแนะนำอาชีพไม่ได้กล่าวว่าระบบออกเอกสารแทนผู้ใช้
- แก้ `dashboard.empty.description` ซึ่งเป็นข้อความเก่าที่ไม่มี caller ปัจจุบัน; ไม่เปลี่ยน `widgets.goalProgress.empty.description` ที่ใช้อยู่และไม่ได้อ้างการแตกแผนอัตโนมัติ

รอบตรวจนี้เป็น static catalog/source audit ครบชุด ร่วมกับ browser spot checks และ regression tests ที่ระบุด้านล่าง ไม่ใช่การพิสูจน์ทุกข้อความในทุก runtime state หรือการทดสอบบนอุปกรณ์ iPad จริง
