# ลดขั้นตอนการใช้งาน Kemtit

วันที่: 2026-10-02 · สถานะ: ดำเนินการและผ่านการตรวจ local ในขอบเขตนี้แล้ว

## เป้าหมายและขอบเขต

ลดการกรอกข้อมูล การตัดสินใจซ้ำ และการเปลี่ยนหน้าระหว่างการบันทึกกับการวางแผน โดยรักษาการจัดเก็บ canonical records การแสดงผลข้ามหน้า และสิทธิ์การเข้าถึงเดิม ใช้ `/prototype` ปัจจุบันเป็น style reference: พื้นผิวเรียบ ข้อมูลหลักชัด ตัวเลือกเสริมเปิดเมื่อต้องการ และปุ่มหลักหนึ่งจุดต่อกิจกรรม ไม่ย้ายข้อมูลตัวอย่างหรือ localStorage ของ Prototype มาเป็นข้อมูลจริง

คำสั่งผู้ใช้ครั้งนี้อนุญาตให้วิเคราะห์ วางแผน และปรับ workflow โดยใช้ Prototype เป็นสไตล์ ขอบเขตรุ่นนี้คือวงจรที่ใช้ซ้ำทุกวัน: Capture → Review preview → Confirm → Today → Plan → Schedule การจัดหน้าใหม่ทั้งระบบและ batches D–G ในแผน UI เดิมยังไม่ได้ถือว่าเสร็จจากงานนี้

## สัญญาพฤติกรรมของรุ่นนี้

### ลำดับการใช้งานตามอาชีพและระดับแผน

เพิ่มเติมตามคำขอผู้ใช้: UI ต้องบอกลำดับก่อนหลัง ไม่เพียงลดจำนวนช่องกรอก ใช้บทบาทที่บันทึกไว้จริง; บัญชีเก่าที่ไม่มีบทบาทใช้คำแนะนำทั่วไป ไม่เดาอาชีพ

| อาชีพ | ปี: ทิศทาง | เดือน: ผลลัพธ์ที่ส่งมอบ | สัปดาห์: แบ่งงานตามเวลาจริง | วันนี้: ลงมือ |
| --- | --- | --- | --- | --- |
| พนักงาน | เป้าหมายงาน/การพัฒนา → จุดตรวจรายเดือน → ทบทวนผล | เลือกผลส่งมอบ → แตกงานที่เชื่อมเป้าหมาย → ตรวจความคืบหน้า | ตรวจนัดและกำหนดส่ง → เลือกงานส่งมอบสำคัญ → จองเวลาทำงาน | ดูนัด/งานถึงกำหนด → ยืนยันงานสำคัญไม่เกิน 3 → ทำและติ๊กเสร็จ |
| ผู้ขาย/ร้านค้า | เป้าหมายธุรกิจ → แผนสินค้า/ช่วงขาย → ทบทวนผล | เลือกสินค้า/แคมเปญ → แบ่งงานเตรียมและติดตาม → ตรวจยอด/ค่าใช้จ่ายที่บันทึกจริง | ตรวจงานส่งมอบ/บิล → เลือกงานขายและงานเตรียม → จองเวลาและตรวจสัปดาห์ | ดูงานส่งมอบ/บิลถึงกำหนด → ยืนยันงานสำคัญ → ทำและบันทึกรายการจริง |
| นักเรียน/นักศึกษา | เป้าหมายการเรียน → จุดตรวจวิชา/ทักษะ → ทบทวนผล | เลือกงานส่ง/ผลการเรียนรู้ → แบ่งงานศึกษา → ตรวจความคืบหน้า | ตรวจตารางเรียน/สอบ/งานส่ง → เลือกเนื้อหาหรืองานหลัก → จองเวลาอ่านและทบทวน | ดูเรียน/สอบ/งานถึงกำหนด → ยืนยันงานสำคัญ → ทำและบันทึกความคืบหน้า |
| ฟรีแลนซ์ | เป้าหมายงาน/ทักษะ → จุดตรวจงานลูกค้า → ทบทวนผล | เลือกสิ่งส่งมอบลูกค้า → แบ่งงานตามช่วงส่ง → ติดตามความคืบหน้า | ตรวจนัด/กำหนดส่ง → เลือกงานลูกค้าสำคัญ → จองเวลาทำงานและติดตาม | ดูนัด/ส่งงาน/รายการเงินถึงกำหนด → ยืนยันงานสำคัญ → ส่งมอบและบันทึกผล |

ปี → เดือน → สัปดาห์ → วันนี้ เป็นลำดับการแตกเป้าหมาย ไม่ใช่ประตูบังคับ ผู้ใช้เริ่มที่วันนี้หรือ Inbox ได้ทันที คำแนะนำจะใช้ภาษาตามอาชีพและมีลิงก์ไปขั้นถัดไปโดยใช้วันที่/ช่วงแผนที่เลือก

ลำดับความสำคัญของงานที่เสนอใน Today: deadline ที่เลยหรือถึงวันนี้ → งานที่วางแผนค้าง/ถึงวันนี้ → priority ที่ผู้ใช้ตั้ง → ความเชื่อมโยงกับ goal/project → ลำดับเดิมเมื่อคะแนนเท่ากัน บทบาทใช้ปรับคำแนะนำ ไม่เปลี่ยนความเร่งด่วนของข้อมูลจริง รายการที่ยืนยันไว้ยังมาก่อนคำแนะนำใหม่

1. พิมพ์หรือเปิดหน้าไม่มีการบันทึกข้อมูลธุรกิจ คำแนะนำเป็น preview จนกดบันทึก
2. Quick Capture ใช้ action, validation, authentication และ request idempotency เดิม ข้อผิดพลาดต้องคงข้อความที่กรอกและให้ลองใหม่ได้
3. ค่าที่ระบบเตรียมให้ต้องเห็นก่อนบันทึก ได้แก่ชนิด หมวด วัน จำนวนเงิน ระยะเวลา และการทำซ้ำตามชนิดรายการ สามารถเปลี่ยนชนิดได้
4. ข้อมูลในแผนที่บันทึกแล้วต้องไม่ถูกแทนด้วยคำแนะนำ รวมถึง priority ที่ตั้งใจเว้นว่าง notes และเวลาที่ผู้ใช้กำหนดเอง
5. รายการสำคัญไม่เกิน 3 task IDs ที่ไม่ซ้ำ; รายการที่เลือกไว้ใน scope อื่นยังคงอยู่หากยัง eligible
6. งบเวลารายวันและเวลาที่จัดไว้ต้องไม่ถูกหักซ้ำ: default budget ใช้ free minutes + planned block minutes ตาม contract ของ `calculateEffectiveAvailableMinutes`
7. การเสนอเวลาใช้ free intervals จาก availability เดิม เคารพช่วงงาน พัก เหตุการณ์ และ blocks เดิม; การยืนยันยังผ่านการตรวจ conflict ฝั่ง server
8. การจอง recurring task เก็บ occurrence source date และ scheduled date เดิม ไม่เปลี่ยนตัวตนของ occurrence
9. รักษา TH/EN ทั้งข้อความที่มองเห็นและ accessible labels; ใช้ component และ tokens เดิม ไม่มี dependency หรือ database migration ใหม่

## การวัดจำนวนขั้นตอน

นับการกดปุ่มหลักหลังเปิดฟอร์ม แยกจากการพิมพ์หนึ่งครั้งและการแก้ตัวเลือกตามความต้องการ ไม่รวม login หรือ navigation ที่เหมือนกันก่อนและหลัง

| กิจกรรมทั่วไป | ก่อน | เป้าหมายหลังปรับ |
| --- | --- | --- |
| Capture ข้อมูลครบ | เตรียมรายการ + ยืนยัน = 2 ปุ่ม | ยืนยัน = 1 ปุ่ม หลังเห็น live preview |
| แผนใหม่ 3 งาน | เลือก 3 งาน + บันทึก = 4 ปุ่ม | ตรวจข้อเสนอ + บันทึก = 1 ปุ่ม หากยอมรับรายการที่แนะนำ |
| จองเวลาให้งานแรก | ตรวจ/แก้เวลาเริ่มและจบ + บันทึก | ตรวจช่วงเวลาที่เสนอ + บันทึก = 1 ปุ่ม เมื่อมีช่องว่างพอ |
| แก้แผนที่บันทึกแล้ว | แก้ค่าที่ต้องการ + บันทึก | คงเดิมเพื่อรักษาความตั้งใจผู้ใช้ |

นี่เป็นตัวชี้วัด interaction จากเส้นทางที่กำหนด ไม่ใช่หลักฐานว่า retention หรือความสนใจเพิ่มแล้ว หลังนำขึ้นใช้งานควรวัด time-to-first-save, capture abandonment, จำนวนการแก้ค่าที่แนะนำ, scheduling conflict และการกลับมาใช้งาน 7 วัน เทียบ baseline โดยไม่เก็บข้อความงาน/บันทึกส่วนตัวใน analytics

## ขอบเขตการยืนยันผล

ทดสอบกับ local development และข้อมูล QA เท่านั้น ไม่ถือว่าเป็น hosted production validation ไม่เปลี่ยน OAuth, notification delivery, schema, ข้อมูลเดิม หรือ deployment settings เพื่อให้ผลทดสอบผ่าน และไม่สรุปว่าผู้ใช้มี engagement ดีขึ้นจนกว่าจะมีข้อมูลการใช้งานจริง
