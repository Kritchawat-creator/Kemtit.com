# ตรวจต้นแบบ Kemtit Planner

วันที่ 22 กันยายน 2026

## ขอบเขต

แยกการตรวจต้นแบบ HTML/JavaScript นี้ออกจากแอป Next.js และฐานข้อมูลจริง การผ่าน interaction ในต้นแบบไม่ยืนยัน server authorization, RLS, transaction, calendar OAuth, LINE delivery หรือความถูกต้องของ migration

## เกณฑ์ตรวจต้นแบบ

- ทุกหน้าที่ระบุในแผนเปิดได้และมีเนื้อหาตรงวัตถุประสงค์
- เห็นป้ายข้อมูลตัวอย่างและรีเซ็ตการทดลองได้
- Capture งานที่ยังไม่กำหนดวันเข้ากล่องรับเข้า จากนั้นนำงานเดิมไป Today ได้
- ข้อเสนอรายวันแสดงเวลาที่มี เวลาที่ถูกจอง และปริมาณงานแยกกัน
- ปรับแผนมี preview ก่อน confirm และย้อนกลับได้ โดยกำหนดส่งเดิมคงอยู่
- การบันทึกจ่ายบิลเป็นการจำลอง และไม่เพิ่มรายจ่ายซ้ำเมื่อทำซ้ำ
- Review ส่งสิ่งที่จะทำต่อไปยังแผนสัปดาห์หน้าที่มองเห็นได้
- หน้า Settings/เชื่อมต่อ/Login ระบุขอบเขตทดลอง ไม่ทำให้เข้าใจว่าเชื่อมบัญชีจริงแล้ว
- ข้อความและปุ่มหลักไม่ล้นหน้าจอบนมือถือ และเข้าถึงด้วย keyboard ได้
- JavaScript syntax และ browser console ไม่มี error ที่ขัดขวางการใช้งานในเส้นทางที่ตรวจ

## ผลตรวจต้นแบบใน browser

- เปิดทั้ง 21 routes จากสารบัญได้ มีเนื้อหาจริงของหน้า ไม่มีหน้า placeholder (ตรวจ desktop และ mobile)
- ที่ viewport 390 × 844 ทั้ง 21 routes มี document width 390 ไม่มี horizontal overflow ระดับหน้า
- Finance: กด “จำลองจ่าย” บิล 420 ทำให้รายจ่ายจาก 690 เป็น 1,110 บาท ปุ่มจ่ายถูกแทนด้วยสถานะจ่ายแล้ว; reload แล้วยังคงยอดเดิม ไม่มีปุ่มสร้างรายการซ้ำสำหรับบิลที่จ่ายแล้ว
- Browser console ไม่มี error ระหว่าง route smoke และ Finance flow ข้างต้น
- โหมดเริ่มครั้งแรก: พิมพ์ `เตรียมใบเสนอราคาทดลอง` แล้วกด “บันทึกวันนี้” หนึ่งครั้ง ได้งานหนึ่งรายการ; reload แล้วยังอยู่และไม่แสดงสถิติ/นัดตัวอย่างใน Today
- ทำเครื่องหมายงานแรกเสร็จด้วยหนึ่ง click และกด checkbox เดิมเปิดกลับมาทำต่อได้
- Quick Capture: เลือก Inbox และบันทึก `ไอเดียแพ็กเกจใหม่` ได้โดยไม่มีหน้าต่างยืนยันรอบสอง จาก Inbox กด “ใส่วันนี้” แล้วรายการหายจาก Inbox และปรากฏใน Today หนึ่งรายการ
- Goal → เพิ่ม next action: งานใหม่ปรากฏใน Goal Detail และ Today หนึ่งรายการ โดยไม่ต้องเลือกงานตัวอย่างเดิม
- Focus: เปิดหน้าตรงโดยยังไม่ได้เลือก focusTaskId แล้วกด “ทำเสร็จแล้ว” ได้; Today แสดงสถานะเสร็จของงานเดียวกัน และเปิดกลับมาทำต่อได้
- Review: ยืนยันย้ายงานใหม่ไป 28 ก.ย. แล้ว Plan แสดงงานในกลุ่มวันที่ 28 ก.ย.; “นำกลับวันเดิม” คืนงานเข้า Today หนึ่งรายการ
- ปุ่มชื่อรายการงาน โปรไฟล์ และเมนูล่างมือถือมี styling ชัดเจน; ตรวจทั้ง 21 routes ที่ 390 × 844 ไม่พบปุ่มที่มองเห็นได้ใช้กรอบ `outset` เริ่มต้นของ browser
- Modal บันทึกเร็วโฟกัสช่องกรอก; Escape ปิดและคืน focus ไปปุ่มเปิด ตรวจใน browser แล้ว
- Google Sign-in: ปุ่มเปิด dialog จำลอง; ยกเลิกแล้วอยู่หน้า Login และ dialog ปิด; กดจำลองสำเร็จแสดงปุ่ม disabled ระหว่างรอ แล้วกลับ Today โดยงานตัวอย่างเดิม 4 รายการและ Inbox 2 รายการยังอยู่ ไม่ได้ทดสอบ OAuth จริง
- หน้า Login รุ่นสุดท้ายไม่มีช่องรหัสผ่าน มี Google และอีเมลเป็นทางเลือก; เครื่องหมาย Google โหลดได้ และหน้าไม่ล้นที่ 390px
- Rescue: ยืนยันนัดด่วน 13:30–14:30 แล้วงานสรุปยอดขายและไฟล์แนบย้ายเป็น 23 ก.ย. ใน Plan และ Calendar เดือน งานข้อเสนอยังคง 22 ก.ย. และกำหนดส่งเดิม 23/25 ก.ย. ยังอยู่; Undo คืนงานทั้งสองเป็น 22 ก.ย. และนัดด่วนหายไป
- หลังปรับแผน capacity เป็นงาน 2 ชม. + ช่วงที่ล็อก 3 ชม. + พัก 1 ชม. + ว่าง 2 ชม. รวม 8 ชม. ไม่มีการหักนัดด่วนซ้ำ
- Review แสดงคำเตือนก่อนย้ายงานที่ deadline 25 ก.ย. ไป 28 ก.ย.; Plan สัปดาห์แสดงงานในส่วนถัดจากสัปดาห์นี้ และคง deadline เดิมไว้
- แท็บ Plan เดือน/ปีเปลี่ยนกลุ่มข้อมูลตามช่วงจริง; Calendar เดือนแสดงงานที่ย้ายในช่องวันที่ใหม่ ไม่ใช้รายการตัวอย่างที่ฝังตายตัว
- Quick Capture รุ่นสุดท้ายแสดง Inbox เป็นปลายทางเริ่มต้นตรงกับ state (`aria-pressed=true`)
- ตรวจองค์ประกอบ badge/calendar chip ใน Calendar เดือน ไม่พบขอบซ้ายหนาพิเศษ
- ตรวจรอบรวมหลังแก้ Plan/Calendar/Rescue/Google: ทั้ง 21 routes มี heading และเนื้อหา, ไม่ล้นระดับหน้าบน desktop และ 390 × 844, ไม่พบปุ่มกรอบ default ที่มองเห็นได้ และไม่พบ browser console error ใหม่ในรอบตรวจนี้
- `node --check` ผ่านทั้ง `app.js`, `extras.js`, `signature.js`; ตรวจ AST ของ `app.js` ไม่พบ function declaration ชื่อซ้ำหรือ syntax diagnostic
- Sidebar active รุ่นสุดท้ายตาม feedback: ยกเลิกเส้นและรูปข้าวหลามตัดที่อยู่ข้างไอคอน ใช้ตัวอักษรเข้มและไฮไลต์เฉพาะช่วงล่างของชื่อเมนู; ตรวจภาพ Goals/Reviews และ computed style แล้ว `::before`/`::after` เป็น `none`, พื้นแถวโปร่งใส, ไอคอนไม่มี shape ซ้อน และแถบไฮไลต์กว้างตามข้อความ ไม่เต็มแถว
- ฟอนต์รุ่นสุดท้าย: CSS และ `next/font/local` ชี้ไป TTF ต้นฉบับน้ำหนัก 400/500/600; แฮชทั้งสามและ OFL ตรงกับ provenance, ชุด production/prototype byte-identical; ตรวจภาพและ computed font-family ใน browser และ local server บันทึกการโหลดไฟล์ TTF ครบทั้งสาม (`200/304`)
- Google asset รุ่นสุดท้าย: รูปในเครื่องโหลดสำเร็จ natural size 354 × 80 แสดง 177 × 40; ยกเลิก dialog ได้และจำลองสำเร็จกลับ Today ได้ ไม่ได้เชื่อม Google จริง
- ตรวจซ้ำหลังเปลี่ยนฟอนต์/ไอคอนและ active menu (`v=20260922-nav4`): 21 routes ผ่านบน desktop และ viewport 390 × 844 ที่ยืนยันขนาดจาก DOM; ไม่มี page overflow, visible default outset button หรือ console error ใหม่ คืน viewport เดิมหลังตรวจ
- `node --check` รอบสุดท้ายผ่าน `app.js`, `extras.js`, `signature.js` และ `src/styles/theme.ts`; เป็น syntax check ไม่ใช่ production build

## ขอบเขตที่ยังไม่ใช่ระบบจริง

- วันที่อ้างอิงตรึงที่ 22 กันยายน 2026 เพื่อใช้เปรียบเทียบสถานการณ์เดียวกัน ไม่ใช่ปฏิทินที่เลื่อนตามวันปัจจุบัน
- Capture เก็บข้อความตามที่พิมพ์ ยังไม่มีการตีความวัน/เวลาจากภาษาไทยตามข้อเสนอ P3
- ตัวเลข capacity ใช้ข้อมูลและค่าประเมินในเดโม ยังไม่ใช่ scheduling engine ที่ตรวจ union ของทุก busy interval และ timezone
- Calendar สัปดาห์เป็นการจัดรายการลงกลุ่มชั่วโมง 08:00–18:00 ไม่ใช่บล็อกที่มีความสูงตาม duration และยังไม่รองรับ drag/resize; ปี/เดือนของ Plan เป็นการจัดกลุ่มรายการ ไม่ใช่เครื่องมือสร้างเป้าหมายทุกระดับที่เสร็จสมบูรณ์
- ยังไม่ได้จำลอง loading/error/offline/permission ของทุกหน้าครบตาม state contract; รายการในแผนเป็นเกณฑ์สำหรับพัฒนาระบบจริง
- ผล smoke test และเส้นทางที่ระบุด้านบนไม่ใช่คำยืนยันว่าทุกปุ่ม ทุก browser หรือทุกกรณี accessibility ผ่านแล้ว

ใช้เบราว์เซอร์ที่แสดง UI จริงในการตรวจ ไม่ใช้การเห็นชื่อฟังก์ชันใน source เป็นหลักฐานว่าปุ่มทำงาน

## Baseline ของแอปจริงที่ตรวจระหว่างวิเคราะห์

- `./node_modules/.bin/vitest run`: 115 tests ผ่าน, 1 test ข้าม; 25 suites ผ่าน, 1 suite ข้าม, 1 suite ล้มเหลว (`secret-box.server.test.ts` import `server-only` ไม่ได้ใน test environment)
- `./node_modules/.bin/tsc --noEmit --incremental false`: ไม่ผ่าน พบ generated `.next/types` ซ้ำ, story fixtures ขาด `data_origin`, onboarding event payload มี `role` ไม่ตรง type และ nullable recurrence fields ใน task actions
- คำสั่งผ่าน `pnpm` ก่อนหน้านั้นหยุดใน dependency precheck จึงเรียก binaries ที่ติดตั้งอยู่โดยตรงตามรายการด้านบน
- ไม่ได้รัน lint, production build, database integration หรือ E2E ของแอปจริงในงานออกแบบครั้งนี้
- ไม่ได้แก้ production source เพื่อกลบข้อผิดพลาดเหล่านี้ ข้อผิดพลาดเป็นส่วนของ P0 ในแผนพัฒนา
