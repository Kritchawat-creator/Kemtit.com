# Planner: คู่แข่ง จุดขาย และสิ่งที่ Kemtit ควรพิสูจน์

วันที่ตรวจ: 22 กันยายน 2026 · ขอบเขต: เอกสารผลิตภัณฑ์/คู่มือทางการของ Todoist, TickTick, Sunsama, Motion, Structured, Akiflow, Griply และทางเลือกใกล้เคียง Notion กับ LINE Calendar รวม 9 ผลิตภัณฑ์

เอกสารนี้แยกข้อเท็จจริงที่ผู้ผลิตระบุ ออกจากข้อเสนอและสมมติฐานของ Kemtit ไม่ใช่ผลทดสอบใช้งานคู่แข่งจริง ไม่จัดอันดับความนิยม ไม่อ้างว่าจำนวนฟีเจอร์พิสูจน์ประสิทธิผล และไม่ใช้ราคาซึ่งยังไม่จำเป็นต่อการตัดสินจุดขายครั้งนี้

## ข้อเสนอหลัก

Kemtit ไม่ควรขายเพียง “มีเป้าหมาย + Top 3 + ปฏิทิน + AI + รีวิว” เพราะคู่แข่งมีองค์ประกอบเหล่านี้แล้ว ควรทดลองจุดขายที่เฉพาะกว่า: **ช่วยคนทำงานอิสระหรือผู้ประกอบการรายเล็กที่ใช้ภาษาไทย เลือกงานที่พาเป้าหมายไปข้างหน้าให้พอดีกับเวลาจริง และกลับมาจัดการวันได้เร็วเมื่อแผนเปลี่ยน** โดยให้ผู้ใช้เห็นเหตุผล แก้ไขได้ และเชื่อมบทเรียนไปยังแผนถัดไป

นี่เป็นสมมติฐานทางผลิตภัณฑ์ ยังไม่ใช่ความสามารถที่ Kemtit ทำได้ครบแล้วหรือหลักฐานว่าเหนือกว่าคู่แข่ง ความแตกต่างต้องพิสูจน์จากเวลาเริ่มต้นใช้งาน จำนวนขั้นตอน ภาระการกรอกซ้ำ และงานสำคัญที่ทำสำเร็จของกลุ่มเป้าหมาย

### ตรวจคู่เทียบด้านเป้าหมายและพื้นที่ทำงานเพิ่มเติม

| ผลิตภัณฑ์ | สิ่งที่ยืนยันจากคู่มือทางการ | ผลต่อจุดขาย Kemtit |
| --- | --- | --- |
| **Griply** | เชื่อม Life Areas → Vision → Goals → Habits/Tasks; goal เลือก metric และแตก subgoals ได้; มี Inbox/Today/Upcoming, time estimates, deadlines และ time blocking กับ Google/Outlook [เริ่มใช้งาน](https://griply.app/help/get-started), [วางแผนวันและสัปดาห์](https://griply.app/help/get-started/plan-your-day-week) | Goal Cascade และการเชื่อมงานกับชีวิตไม่ใช่ความใหม่ของ Kemtit ต้องเทียบขั้นตอนและผลของ workflow โดยตรง โดยเฉพาะจากเป้าหมายจนถึงการเลือกงานวันนี้ |
| **Notion — ทางเลือกที่ผู้ใช้ประกอบเองได้** | คู่มือ Projects/Tasks เชื่อมการจัดงานกับเอกสารและความรู้ พร้อมมุมมอง table/board/timeline/calendar/list/gallery [คู่มือ Projects and Tasks](https://www.notion.com/en-gb/help/guides/getting-started-with-projects-and-tasks) | ความยืดหยุ่นและการรวมหลายข้อมูลไม่ใช่จุดขายเฉพาะ ข้อเสนอของ Kemtit ต้องพิสูจน์ว่าใช้การตั้งค่าน้อยกว่าและพาผู้ใช้ตัดสินใจได้เร็วกว่า workspace ที่ผู้ใช้มีอยู่ ไม่อนุมานว่า Notion ไม่มีฟังก์ชันอื่นจากคู่มือนี้ |

การเชื่อม Goal → Task จึงเป็นฐานที่ต้องทำดีอยู่แล้ว ความได้เปรียบที่เสนอให้ทดลองคือความต่อเนื่องของการเลือกงานตามเวลาจริง การมองเห็นผลกระทบเมื่อแผนเปลี่ยน และการนำบทเรียนกลับมาใช้ โดยเหมาะกับกลุ่มผู้ใช้ไทยที่กำหนดไว้

## ภาษาไทยและ LINE: โอกาสที่ต้องพิสูจน์ ไม่ใช่ข้ออ้างว่าไม่มีคู่แข่ง

**Todoist Ramble ระบุ Thai ในรายชื่อภาษาที่รองรับแล้ว** จึงไม่ควรใช้ “รับเสียง/ภาษาไทย” เพียงอย่างเดียวเป็นจุดขายที่อ้างว่าไม่มีใครทำ การรองรับเสียงไทยไม่ได้พิสูจน์ว่า UI ไทย, typed date parsing ไทย, การเข้าใจสำนวนเวลาไทย และ workflow ภาษาไทยทำได้ดีเท่ากันทั้งหมด ต้องทดสอบแยก [Todoist Ramble — Languages](https://www.todoist.com/help/todoist/todoist-and-ai/dictate-to-add-tasks-with-ramble-P1Raq7vVF)

สำหรับผลิตภัณฑ์อื่นในตาราง รอบนี้ยังไม่ได้ยืนยันคุณภาพหรือขอบเขตภาษาไทยแบบ end-to-end ส่วนการเชื่อม LINE ของ planner แต่ละเจ้ายังไม่ได้ยืนยัน การค้นครั้งนี้ไม่พอให้พูดว่า “ทุกเจ้าไม่มี LINE” หรือ “Kemtit เป็นเจ้าเดียว”

**LINE Calendar เองเป็นทางเลือกที่ต้องแข่งด้วย:** การเพิ่มนัดหมายและแจ้งเตือนใน LINE มีอยู่แล้ว จึงไม่พอใช้เป็นข้อได้เปรียบเฉพาะของ Kemtit คำถามจริงคือ Kemtit ช่วยเลือกและทำงานที่พาผลลัพธ์ด้านงาน/ชีวิต/เงินไปข้างหน้าได้ดีกว่าการใช้แชทกับปฏิทินเดิมหรือไม่ [คู่มือ LINE](https://help2.line.me/line/smartphone/sp?contentId=200002132&lang=th)

ไม่พบหลักฐาน API สาธารณะของ LINE Calendar ที่ยืนยันในงานนี้ จึงไม่เสนอว่ามี native calendar integration ให้ต่อใช้ได้ทันที และแยก LINE messaging/deep-link workflow ของ Kemtit ออกจาก LINE Calendar อย่างชัดเจน

Kemtit มีฐาน notification ผ่าน LINE อยู่ใน source แต่ยังไม่ควรนำเสนอว่า capture/สนทนา/ปรับแผนผ่าน LINE ครบแล้วเพียงเพราะส่งแจ้งเตือนได้ การสร้าง action เพิ่มเป็นงานอนาคต และต้องตรวจการทำงานจริงก่อนใช้เป็นคำสัญญาสินค้า [notification generator](../src/shared-services/jobs/generate-v2-notifications.ts), [notification processor](../src/shared-services/events/processor.ts)

## สิ่งที่เป็นมาตรฐานการแข่งขัน และสิ่งที่ยังไม่ใช่จุดขายเฉพาะ

ข้อสรุปส่วนนี้เป็นการตีความจากตารางด้านบน:

- **ควรทำให้ดีเป็นพื้นฐาน:** capture เร็ว, recurrence, reminder ที่ควบคุมได้, mobile ใช้ง่าย, calendar เชื่อถือได้, แยกวันลงมือทำกับ deadline, time estimate และการแก้งานค้างโดยไม่ต้องกรอกซ้ำ
- **ไม่ใช่ความใหม่ด้วยตัวเอง:** Top 3 (Akiflow มี 2–3 goals), capacity/timeboxing (Sunsama/Motion), auto-replan (Motion/Structured/Akiflow), goal-to-task และ weekly review (Sunsama), habit/Pomodoro (TickTick), natural-language capture/เสียงไทย (Todoist Ramble), นัดหมายและการเตือนใน LINE (LINE Calendar)
- **ไม่ควรเพิ่มเพื่อให้ดูครบ:** AI chat ทั่วไป, dashboards จำนวนมาก, marketplace, social feed หรือ integrations จำนวนมาก โดยยังไม่รู้ว่าช่วยกลุ่มเป้าหมายทำงานสำคัญได้ดีขึ้นอย่างไร
- **Workflow มีคุณค่าเมื่อช่วยการตัดสินใจ:** “ควรทำอะไร → ใส่ได้จริงไหม → งานแทรกแล้วตัดอะไร → เรียนรู้อะไรสำหรับสัปดาห์หน้า” ต้องเชื่อมกันได้ในจำนวนขั้นตอนน้อย การมีหน้าแต่ละหน้าแยกกันยังไม่เท่ากับมี workflow ที่ดี

## สมมติฐานจุดขายที่ควรทดลอง

### 1. จากเป้าหมายของคนทำงานคนเดียวสู่แผนวันนี้ที่ทำได้จริง — ตัวเลือกหลัก

กลุ่มเริ่มต้น: ผู้ขายรายเล็ก/ฟรีแลนซ์ที่ต้องรับผิดชอบทั้งงานหาเงิน งานส่งมอบ และเรื่องส่วนตัว ใช้ภาษาไทยและมีงานแทรกระหว่างวัน เป็นกลุ่มที่ควรสัมภาษณ์ก่อน ไม่ใช่ข้อสรุปว่ามี demand หรือยอมจ่ายแล้ว

ประสบการณ์เสนอ: ตั้งผลลัพธ์หนึ่งข้อ → เลือกงานที่ช่วยผลลัพธ์นั้น → หักนัดหมาย/เวลาพักจากเวลาที่มี → เลือกงานสำคัญให้พอดี → เห็นทันทีว่างานไหนยังไม่มีเวลารองรับ เป้าหมายเช่นยอดขายต้องใช้ข้อมูลยอดจริง ไม่อนุมานว่า checklist เสร็จเท่ากับทำรายได้สำเร็จ

ความแตกต่างที่อาจสร้างได้: template/คำถาม/หน่วยวัดและ flow ที่เฉพาะกลุ่ม ลดการตั้งค่าระหว่างหลายแอป พร้อมแยกตัววัดผลลัพธ์จริงจากจำนวนงาน สิ่งนี้ต้องดีกว่าใช้ Sunsama objectives + tasks หรือ Todoist project ธรรมดาในการทดลองเดียวกัน มิฉะนั้นไม่ใช่เหตุผลให้เปลี่ยนมาใช้

### 2. วันสะดุดแล้วกลับมาคุมงานได้เร็ว

ประสบการณ์เสนอ: ผู้ใช้บอก “วันนี้เหลือ 90 นาที” → ระบบแสดงงานที่ยังพอทำ งานที่ควรเลื่อน และผลต่อ deadline/เป้าหมาย → ผู้ใช้ยืนยันการเปลี่ยน → undo ได้ → ปิดวันด้วยการเลือกเหตุผลสั้น ๆ เพื่อนำไปปรับ estimate/แผนครั้งหน้า

การเลื่อนงานอัตโนมัติไม่ใช่จุดขายใหม่; สมมติฐานคือ Kemtit อธิบาย trade-off ด้วยภาษาของผู้ใช้และใช้ขั้นตอนน้อยกว่าทางเลือก เหมาะกับกลุ่มที่ต้องการควบคุมการเปลี่ยนแผนเอง ต้องทดสอบคู่กับ Structured Replan และ Motion ไม่อ้างว่าป้องกัน burnout หรือเพิ่มสุขภาพจิตโดยไม่มีหลักฐาน

### 3. เชื่อม LINE กับการลงมือทำอย่างสั้นและตรงบริบท

ประสบการณ์เสนอ: brief ที่เลือกเวลาได้ → เปิดไปงานสำคัญของวันนี้โดยตรง → ยืนยันเสร็จ/เลื่อนอย่างมีบริบท → สรุปผลและต่อแผนโดยไม่ต้องหาเมนูใหม่ หากทดสอบแล้วคนยังต้องเปิดแอปและกรอกซ้ำหลายครั้ง ให้แก้ flow ก่อนเพิ่ม chatbot

ความแตกต่างที่อาจสร้างได้คือการเชื่อม brief → การตัดสินใจ → task outcome → แผนใหม่ในช่องทางที่กลุ่มทดลองใช้อยู่ ไม่ใช่แค่มี notification เพราะ LINE Calendar ให้ประโยชน์เรื่องนัดหมายและเตือนได้อยู่แล้ว ควรเป็นส่วนเสริมของข้อ 1–2 หลังระบบหลักเชื่อถือได้ ไม่ทำให้ LINE เป็นข้อบังคับในการใช้งาน Kemtit

## พิสูจน์ว่า “ตอบโจทย์กว่า” อย่างไร

1. **สัมภาษณ์และทดสอบต้นแบบกับ 6–8 คนในกลุ่มเดียวกัน:** ให้จัดงานจากข้อความไทย/ตารางจริง 10–15 รายการ เลือกงานสำคัญ แล้วใส่งานแทรกหนึ่งรายการ เปรียบเทียบเครื่องมือที่แต่ละคนใช้อยู่กับต้นแบบ Kemtit รวมผู้ใช้ที่ใช้ LINE Calendar/แชทเป็นวิธีเดิมด้วย สลับลำดับการทดสอบ เก็บ task success, เวลารวม, จำนวนครั้งกรอกข้อมูลเดิม, งานชน/งานล้นที่ผู้ใช้มองไม่เห็น และเหตุผลเลือก/ไม่เลือกใช้
2. **Pilot สองสัปดาห์เมื่อระบบพร้อม:** วัดเวลาวางแผนต่อวัน, อัตราทำ priority ที่ commit สำเร็จ, งานเลื่อนที่กลับมาทำสำเร็จ, review ที่นำไปปรับแผนจริง, สัดส่วนกลับมาใช้และ reminder mute/unlink ใช้ baseline ต่อคน รายงาน dropout ด้วย ไม่ใช้ task count เป็นตัวแทน productivity เพียงค่าเดียว
3. **เกณฑ์ก่อนสร้าง feature เพิ่ม:** ผู้ใช้ต้องบอกได้ว่า Kemtit ช่วยการตัดสินใจใดดีกว่าเดิม และทำ scenario สำคัญสำเร็จโดยไม่ต้องอธิบาย UI ให้ตลอด หากยังต้องกรอกหลายหน้า ให้ลดขั้นตอนก่อนเพิ่มฟีเจอร์ ผล sample เล็กใช้กำหนดทิศทาง ไม่ใช่พิสูจน์ superiority ทางสถิติ

เป้าหมายทดลองที่ตั้งได้ เช่น median planning time ลดลงจาก baseline อย่างน้อย 25% โดย plan errors ไม่เพิ่ม เป็น **เกณฑ์ทดลองที่เสนอ** ไม่ใช่ผลที่วัดได้แล้ว ตัวชี้วัดรายได้หรือ outcome ระยะยาวต้องแยกจากการทดลอง UX ระยะสั้น

## ขอบเขตงานและความน่าเชื่อถือของเอกสารนี้

- อ่านเว็บไซต์ทางการ ณ วันที่ระบุ; ข้อความการตลาด เช่นลดเวลาหรือเพิ่มประสิทธิภาพ เป็นคำกล่าวของผู้ผลิต ไม่ได้นำมาใช้เป็นผลลัพธ์ที่พิสูจน์แล้ว
- ไม่มีการสมัครแพ็กเกจ ทดลอง sync ด้วยบัญชีจริง ซื้อสินค้า ส่งข้อความ หรือเปลี่ยน production
- เพิ่มเฉพาะเอกสารนี้ ไม่แก้ production code และไม่ commit
- GitNexus impact ของชื่อไฟล์ใหม่คืน UNKNOWN เพราะยังไม่มี target ใน graph; ตรวจแล้วไม่มีไฟล์เดิมและไม่มี reference ชื่อนี้ใน docs/src/e2e/.github ก่อนเพิ่ม ไม่ตีความ UNKNOWN ว่าโค้ดปลอดผลกระทบ
- หลักฐานคู่แข่งไม่ทำให้ runtime verification ของ Kemtit ผ่าน ต้องใช้ผลทดสอบปัจจุบันประกอบก่อนวางแผน release
