# จำลองการใช้งานตามอาชีพ

วันที่: 2026-10-02 · สถานะ: ผ่านการตรวจ local ตามขอบเขตด้านล่าง

ทดสอบครบ 4 บทบาทที่ระบบมีจริง: employee, seller, student, freelancer ใช้บัญชีและข้อมูล QA บน local Supabase ไม่ใช้ข้อมูลลูกค้าหรือธุรกรรมเงินจริง ผลนี้เป็นการจำลองสถานการณ์ตามบทบาท ไม่ใช่ usability research จากผู้ใช้จริง

## สถานการณ์และลำดับความสำคัญ

| บทบาท | สิ่งที่ผู้ใช้พยายามทำ | สิ่งที่ต้องเห็นก่อน | เส้นทางที่ตรวจ |
| --- | --- | --- | --- |
| พนักงาน | ส่งรายงานและจัดการประชุมโดยไม่บันทึกซ้ำหลายหน้า | งานถึงกำหนด/นัดหมาย → งานส่งมอบที่เลือก → งานอื่น | onboarding → แผนเดือน/เป้าหมาย → capture task/note + นัดหมายระบุเวลา → Today → Calendar → เปิดใหม่ |
| ผู้ขาย | เตรียมงานขาย พร้อมเห็นบิลและรายจ่ายจริง | สิ่งส่งมอบ/บิลถึงกำหนด → งานขายหลัก → งานเตรียม | onboarding → แผนเดือน → capture task/bill/expense → Today/Finance/Calendar → เปิดใหม่ |
| นักเรียน/นักศึกษา | ส่งงานและเตรียมอ่านหนังสือ พร้อมกิจวัตรทบทวน | กำหนดส่ง/สอบ → งานเรียนสำคัญ → ทบทวน | onboarding → เป้าหมายเรียน → capture task/habit → Today/Life/Calendar → เปิดใหม่ |
| ฟรีแลนซ์ | วางแผนส่งงานลูกค้า แยกโปรเจกต์และติดตามรายการเงิน | นัด/กำหนดส่งลูกค้า → งานที่เลือก → งานบริหาร | onboarding → เป้าหมาย/โปรเจกต์ → task/expense → Today/Work/Finance → เปิดใหม่ |

สำหรับทุกบทบาท: เปิดแผนปี เดือน สัปดาห์ และ Today; ตรวจข้อความและลำดับ 1–3 ที่ต่างตามบทบาท ตรวจลิงก์ช่วงวันที่เดิม และตรวจว่าคำแนะนำไม่ได้สร้างข้อมูลเอง

## เกณฑ์ผ่าน

- ข้อมูลครบแล้ว Capture มีเพียงปุ่มยืนยันบันทึกครั้งเดียว; ข้อมูลขาดต้องบอกเฉพาะจุดที่ต้องเติม
- งานที่เลือกเป็น priorities แสดงก่อนงานอื่นและยังอยู่หลัง reload
- แผนที่บันทึกแล้วไม่ถูกคำแนะนำเขียนทับ
- ข้อมูลหนึ่งรายการแสดงในหน้าที่เกี่ยวข้องโดยรักษาชนิด task/event/bill/expense/habit/note ของตัวเอง
- จำนวนเงินทศนิยมและวันไม่เปลี่ยนระหว่าง preview → save → readback
- งานที่เกิดซ้ำและ conflict ของ time block ยังคงข้อจำกัดเดิม
- คำแนะนำ 4×4 มีลำดับก่อนหลังและทางลัด แต่ไม่บังคับทำแผนครบทุกระดับ
- จอ 1440, 1024, 768, 390 และ 360px อ่านและกดใช้งานได้ ไม่มี horizontal overflow ที่ระดับหน้าในชุดคำแนะนำ
- ภาษา TH/EN และ accessible labels ของส่วนเพิ่มใหม่ตรงกับภาษาที่เลือก

## สิ่งที่พบและปรับจากการจำลอง

- **มือถือเห็นงานช้า:** คำแนะนำเหนือสรุปตัวเลขดันงานจริงออกนอกหน้าจอแรก ย้ายคำแนะนำ Today มาอยู่ใกล้การตั้งค่าแผน หลังส่วนลงมือทำบนมือถือ และอยู่คอลัมน์เสริมบน desktop; ตรวจภาพ 390px แล้วเห็นงานในหน้าจอแรก
- **คำอธิบายยาว:** ย้ายรายละเอียดการจัดลำดับงานเข้า disclosure คงขั้นถัดไปให้เห็นทันที; ปุ่มช่วงแผนและ disclosure สูงอย่างน้อย 44px
- **Capture:** ย่อข้อความช่วยเหลือและย้ายคำอธิบาย smart defaults เข้า “แก้รายละเอียด”; ผู้ใช้เห็นชนิด วัน และยอดที่ต้องบันทึกก่อน โดยไม่ต้องอ่านคำอธิบายซ้ำ
- **ข้อความปุ่มคลุมเครือ:** ใช้ “ตั้งเป้าหมายช่วงนี้”, “ดูทั้ง 3 ขั้นตอน” และ “Go to today's tasks” ให้ตรงกับผลของการกด
- **ยังไม่เลือกงาน:** เปลี่ยนข้อความระยะเวลาเริ่มต้นให้เป็นกลาง ไม่กล่าวถึง “งานนี้” ในขณะที่ยังไม่ได้เชื่อมงาน
- **ประชุมไม่มีเวลา:** Capture ของกิจกรรมทั้งวันทำให้ availability ไม่มีช่องว่าง เป็นพฤติกรรมที่ถูกต้อง ไม่เพิ่ม slot ปลอมเพื่อให้กดได้; สถานการณ์ประชุมแบบระบุเวลาต้องใช้ข้อมูลเวลาจริง
- **โปรเจกต์:** ปุ่มเพิ่มงานจริงส่ง project context มาให้อยู่แล้ว; การทดสอบต้องกดปุ่มจริงและยืนยันค่าเริ่มต้น ไม่สร้าง URL ที่ตัด context ออกแล้วให้ผู้ใช้เลือกซ้ำ
- **ภาษา:** ตรวจ Today, employee guide และ Capture ภาษาอังกฤษจริงใน in-app browser; ข้อความใหม่และ accessible labels เป็นอังกฤษ ส่วนชื่อที่ผู้ใช้กรอกยังคงเดิม จากนั้นคืนบัญชีทดสอบเป็นไทย

หมายเหตุ: ชุด E2E ระยะแรกพบ selector คลุมเครือเพราะชื่อเดียวกันอยู่ทั้งสรุป/รายการ/select option และ setup บางจุดไม่ตรงเส้นทางจริง แก้ให้ scope ตามหน้าที่ของรายการและใช้ปุ่มจริง โดยไม่ลดข้อกำหนดเรื่องการจัดเก็บข้อมูล

## ข้อจำกัดที่ต้องแยกจากผล local

ไม่ครอบคลุมการส่งแจ้งเตือนจริง Google OAuth ที่ hosted environment หรือการเพิ่ม engagement/retention ในการใช้งานจริง ข้อมูลตัวอย่างอาชีพไม่ได้ทำให้ระบบเป็นระบบบัญชี การขาย หรือระบบจัดการเรียนเต็มรูปแบบ งานนี้ตรวจความต่อเนื่องของความสามารถที่ Kemtit มีอยู่

การตรวจ tablet ใช้ Chromium ที่ viewport 768×1024 และ 1024×768 และตรวจ 360/390/1440px เพิ่ม ไม่ใช่การยืนยันบน iPad Safari เครื่องจริง ยังควรตรวจแป้นพิมพ์สัมผัส/date picker และการใช้งานแนวนอนบนอุปกรณ์จริงก่อน release
